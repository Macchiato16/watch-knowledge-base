# 腕表业务知识库技术方案

版本：0.12（技术设计稿）  
编写日期：2026-11-15  
关联文档：[需求文档](./需求文档.md)

## 1. 方案结论与状态

建议采用 VitePress 静态文档站：Markdown 保存正文，VitePress 生成网页，Git 保存正式内容与修改历史。采用默认主题并优化手机阅读，额外开发腕表结构 3D 交互与复杂功能动画组件，不配置数据库和业务后端。

建议以 GitHub 仓库配合 Cloudflare Pages 自动部署，先用免费网址进行实际网络试用，再确定长期托管及域名。此为拟采用方案，目前尚未安装依赖、创建远程仓库或配置部署。

## 2. 技术栈

| 层次 | 选择 | 用途 |
| --- | --- | --- |
| 文档框架 | VitePress 稳定版 | 路由、导航、文档主题、文章构建 |
| 页面与定制 | Vue 3、TypeScript、CSS | 配置、主题扩展和必要的交互 |
| 结构 3D（已确认） | Three.js + OrbitControls | 代码建模、旋转缩放、部件选取与展开演示 |
| 构建工具 | Vite（随 VitePress 配套） | 开发预览与生产构建 |
| 内容 | Markdown + 本地图片 + 模型及动画资源 | 文章、图例、表格、结构演示和功能动画 |
| 开发环境 | 受支持的 Node.js LTS、npm | 安装依赖、预览、生成网站 |
| 内容版本 | Git | 正式内容历史、回退、更新时间 |
| 搜索 | VitePress 本地搜索 | 浏览器内检索标题和正文 |
| 托管 | Cloudflare Pages（建议） | 构建、HTTPS 和静态资源发布 |

调研时 VitePress 的 v1 文档标示版本为 1.6.4，主站展示 2.0 alpha。实施时核实稳定发行版与 Node.js 要求，固定依赖版本并提交 `package-lock.json`，不直接以 alpha 版本作为第一版基线。框架内的 Vite、Vue 版本按兼容要求选择。

Node.js 只用于开发与构建；上线产物是 HTML、CSS、JavaScript 和图片，无需 PHP、数据库或持续运行的 Node.js 服务。

## 3. 架构与更新路径

```text
收集并核实公开来源
        ↓ 整理为正式文章
Markdown + 配图 + 演示组件及资源 + 网站配置（进入 Git）
        ↓ 提交并推送
GitHub 仓库
        ↓ 触发构建
Cloudflare Pages → 静态网页 → 员工手机浏览器
```

正式网站公开访问；用于部署的仓库可以保持私有，仓库可见性与网站访问范围分别配置。Git 忽略仅控制本地文件是否进入提交，发布范围另由文档根目录与构建配置控制。

## 4. 目录设计与发布范围

需求文档与技术方案存放在 `specs/` 下并纳入 Git 管理；正式网站按 VitePress 常规习惯放到 `docs/`，项目文档不参与网站构建。

```text
├── package-lock.json               # 后续安装时创建
├── specs/

│   └── 技术方案.md                 # 项目文档，进入 Git
└── docs/                           # 正式网站根目录，进入 Git
    ├── .vitepress/
    │   ├── config.ts
    │   └── theme/                  # 演示组件、代码生成模型和主题扩展
    ├── index.md
    ├── general/                    # 通用知识
    │   ├── structure/              # 结构与 3D 演示
    │   ├── materials/              # 材质入门
    │   ├── functions/
    │   │   ├── basic/              # 基本认知：日期、计时、年历、动力存储、双时区
    │   │   └── advanced/           # 深入理解：万年历、三问、双秒追针、陀飞轮、天文星象
    │   └── ecosystem/              # 行业生态
    ├── brands/
    ├── pre-owned/
    ├── cases/
    ├── business/
    ├── faq/
    └── public/
        ├── images/
        └── animations/             # 发布所需的动画资源
```

分类目录为建议命名，随最终内容大纲调整；文件路径建议采用稳定的英文短名，正文标题使用中文。

后续创建工程时忽略 `node_modules/`、`docs/.vitepress/cache/` 和 `docs/.vitepress/dist/`。

构建以 `docs/` 为内容根目录，避免复制整个项目或整个 `specs/`；仅部署 `docs/.vitepress/dist/`。

## 5. 内容、导航与主题

- 每篇正式文章对应一个 Markdown 文件，使用标题层级自动生成文章内目录。
- 侧边栏先手动配置，明确知识的学习顺序；上一篇/下一篇沿用侧边栏顺序。
- 默认主题采用中文界面，设置搜索、目录和更新时间的中文标签。
- 不显示编辑人，不配置在线编辑入口或修订历史界面。
- 内容使用本地图片，图片文件名与文章主题关联；正文配有说明和替代文本。
- 使用系统字体，避免依赖外部字体请求；按需要压缩图片，细节图保留足够清晰度。
- 图片放大优先使用轻量主题扩展；只在默认体验不能满足要求时增加依赖。

### 5.1 通用知识与品牌知识导航

顶部仅设置「通用知识」「品牌知识」两个主导航，搜索独立提供入口。通用知识按「认识腕表结构 → 腕表材质 → 腕表功能 → 腕表行业生态」配置侧边目录；腕表功能下分「基本认知」「深入理解」，不设独立的顶级功能栏目。侧边栏按通用知识或当前品牌切换，手机端折叠展示。文章与演示案例优先围绕百达翡丽、理查米尔，覆盖劳力士，爱彼仅少量涉及；不按四个品牌平均生成内容。

入门内容用于建立认知框架：材质先讲精钢、陶瓷、白金、黄金、玫瑰金、铂金，功能先讲日期、计时、年历、动力存储、双时区，用图文介绍名称、用途和识别，不在基础文章中堆叠深入原理与品牌细节。基础文章通过链接指向后续功能深入文章或品牌篇章，不要求读者先读深入内容才能理解基础正文。

深入的材质差异放在品牌材质专题或具体腕表页；跨品牌通用的功能原理与动画集中放在 `docs/general/functions/advanced/`，品牌／型号页面讲具体实现并引用。品牌材质比较可采用一致的参考维度，包含但不限于物理性质、化学性质和消费者态度；不强制每款腕表套用这些字段。客观参数与市场观察分开写，来源和适用条件保留在可检索的正文中。基础功能五项及复杂功能五类已确认；各专题具体深度、品牌深入材质和收录型号后续细化。

### 5.2 腕表结构 3D 交互与功能动画

已确认使用 Three.js，配合 OrbitControls 和 Vue 组件，代码生成一个基础通用教学模型。尚未安装依赖或实现组件；部件完整、可辨识和说明清楚优先于精细建模。

- 在 Markdown 文章中嵌入 Vue 演示组件，文字仍以可搜索的正文保存。
- 结构模块需要真正可操作的 3D 动画；支持旋转、缩放、点击部件高亮与说明，以及展开／复原。用 OrbitControls 处理视角，部件选取可用射线拾取，展开通过位置插值实现，首期不额外引入动画框架。
- 模型使用基础几何体及曲线生成；游丝使用简化螺旋形状，摆轮和自动陀以示意动作演示，不实现精密机械仿真。提供整表、展开和机芯局部视图，确保内部部件不会被外壳遮挡而无法认识。
- 代码模型覆盖表壳整体、中壳、表镜、底盖、表冠、表带、机芯、自动陀、摆轮和游丝；表壳是整体概念，其组成部件分层标注，机芯内部只先覆盖已确认的教学部件。
- 模型生成逻辑、部件参数和动画代码随演示组件进入 Git，与站点源码一同维护。
- 模型部件与文字使用一致的标识，选中部件可定位相应说明；教学模型的简化范围要写明，不默认准确还原特定品牌机芯。
- 基础功能使用图片和简明正文；通用深入功能讲解及复杂功能动画嵌入腕表功能深入文章，品牌／型号页链接引用。复杂功能优先采用二维示意，确有空间表达需要时再使用三维，不要求所有动画使用同一技术，也不要求入门内容加载复杂功能演示资源。
- 建议为动画提供播放、暂停、重播和必要的分步控制，避免只靠自动播放传递知识。
- 3D 组件用 VitePress 的客户端组件机制加载，并在 Vue 挂载后初始化渲染器；依赖动态导入，避免构建时访问浏览器 API，进入相关章节再加载。
- 对手机限制渲染像素比和几何细分；静止时按需渲染，离开视口或切换页面停止动画，组件卸载时释放几何体、材质和渲染器。
- 手机手势应兼顾页面滚动与模型操作；处理窄屏标签遮挡、横竖屏切换和重复进入页面的资源释放。
- 加载时提供封面与状态提示；设备不支持或加载失败时保留文字、静态图及重试入口。降级阅读不替代正常设备上的 3D 与动画验收。
- 3D 几何结构由代码生成，优先复用几何体并控制细节；模型源码进入 Git，演示代码随站点构建发布。贴图和动画资源按实际需要优化。

新增素材会增加页面体积和制作工作量，但仍可采用静态部署。实施前先完成一个结构演示样例和一个复杂功能动画样例，在员工手机上验证教学准确性、操作体验和加载表现，再扩展完整内容。

### 5.3 品牌专题、型号页面与变种

- 导航按「品牌 → 热门系列 → 具体腕表」配置；品牌材质、型号解读、关联型号与对比记忆与热门系列并列，劳力士增加表带类型。系列清单以需求文档 4.3 节为准。
- 每个型号页面使用独立 Markdown 编写，自由安排标题、图文和演示，不开发强制字段齐全的统一讲解模板。
- 同款腕表默认一个页面承载变种，如 `docs/brands/patek-philippe/nautilus/5711.md`；页面路径使用稳定标识，官方名称与中文俗称用于可见标题和导航。
- 理查米尔的 07、35、55、65、67、72 作为教学目录键；具体文章保存完整官方型号，不根据目录键自动生成型号编号。
- 变种主要记录颜色、表带、联名差异。初期可用 Markdown 图文或表格展示；如需要更清楚的手机体验，再扩展轻量配置卡片组件，不预设复杂筛选或对比工具。
- 变种公共信息可记录名称、图片、差异说明、可确认的完整编号及章节锚点；这些展示字段不约束型号正文，未适用或未确认的编号可不填。
- 差异较大的变种可拆成子文章，保留基础型号页面入口与相互链接，不要求一次预建全部变种。
- 品牌材质、型号规则与劳力士表带知识独立保存，型号页面用链接引用。型号解读由经核实的说明和示例构成，不实现自动型号解码器。
- 品牌特定篇章承载深入材质知识和功能的品牌特有实现；通用功能原理及动画链接腕表功能深入文章，与基础认知文章保持关联，避免重复维护。
- 官方系列名与俗称在正文中同时出现，使两种称呼均能被检索；型号保留原始写法，后续验证带空格、连字符、前导零及完整后缀的搜索表现。
- 本轮仅确定页面结构，不填充未经核实的品牌编码规则、配置编号或具体腕表参数。

#### 劳力士表带内容组织

- 在劳力士品牌下设置独立表带章节，覆盖用户参考图指定的六项：蚝式表带（板带）、纪念型表带（五珠带）、元首型表带（总统带）、橡胶表带、鳄鱼皮表带、PEARLMASTER 表带。
- 先作为一篇图文概览的六个章节组织，使用稳定锚点，便于型号页和配置变种直接引用；内容增多时再拆分子文章。
- 名称与素材以用户参考图作为范围依据；正式正文和图片说明在编写时核对官方名称、材质和实际适配，不将图中俗称自动当作官方材质定义。
- 参考图只用于需求说明，配图后续按网络搜集流程准备；本轮不假定附件已经保存到本地或纳入 Git。

#### 品牌内的关联型号对比

- 每个品牌预留 `comparisons/` 分类，采用独立 Markdown 文章维护每组关联型号，例如 `docs/brands/patek-philippe/comparisons/某组型号.md`（文件名实施时使用英文短名）。
- 一篇文章可比较两个或多个型号，正文包含关系说明、共同点、差异与记忆要点；通过图文或表格呈现，不要求统一参数模板。
- 对比页链接已有型号页，型号页可增加“相关对比”链接；不复制完整型号讲解，也不要求先完成全部型号页才能添加对比内容。
- 区分不同型号之间的对比文章和单型号页面内的配置变种；两者可以互相引用，仍各自维护适合的内容。
- 手机端优先采用纵向图文和差异摘要，宽对比表限制在容器内滚动。初期无需开发动态选表、自动参数对齐或复杂筛选功能。
- 先搭分类结构，实际对比组按需添加，导航仅链接已存在的页面。

### 5.4 通用知识中的腕表功能与渐进扩展

- `docs/general/functions/advanced/` 设置万年历、三问、双秒追针计时、陀飞轮、天文星象五类入口，通用原理与动画随专题维护。
- 天文星象作为分类入口，按后续选定腕表拆分子功能文章和演示，不预设单一动画覆盖所有内容。
- 型号页使用普通 Markdown 链接引用专题，保留简短说明，再讲显示布局、操作、机芯差异和注意事项等具体实现；无需复制专题全文或重复创建同一动画。
- 初期先搭建通用知识、品牌知识两个栏目及其扩展结构，不以收齐系列或型号作为结构交付前提；不自动生成大量无内容的型号页面。
- 入口页区分已有正文与待补充内容；只有实际存在的页面和锚点才加入可点击链接，避免无效占位链接。后续新增文章时同步维护导航与引用。
- 图片从网络搜集，保存来源及必要的使用信息；用于正文的图片按发布需要保存本地优化副本，避免依赖不稳定的外部图片链接。本轮只记录来源方式，不开始素材搜集。

### 5.5 品牌自测题（本阶段暂缓）

用户明确先不处理测试题。本节仅保留后续扩展思路，本阶段不设计题型、不开发组件、不创建题库或作答入口，也不引入成绩存储；不作为当前交付与验收条件。

- 各品牌设置测试题分类，先建立可扩展的结构，题目按需添加；没有题目时不生成空测试页面或无效入口。
- 采用无需登录的自测方式，计划用静态题目数据配合 Vue 组件在浏览器内展示题目、作答和答案解析，无需改变静态站点架构；是否自动判答与评分随题型进一步确定。
- 题目关联答案、解析和已收录知识文章链接；具体题型、答案展示时机及数据字段在细化后设计，不提前绑定统一考试流程。
- 是否评分、保存作答、汇总成绩或识别员工均未确认，不默认使用本地存储或后端数据库保存结果；若以后要求跨设备或集中记录，再单独设计。
- 品牌自测已确认，正式考试管理仍不属于当前范围；先搭结构，题目内容按需补充。

## 6. 搜索实现

初期采用 `themeConfig.search.provider: 'local'`。VitePress 生成搜索索引，浏览器内完成检索，无需额外搜索服务。

搜索范围只包含正式站点文章。中文界面翻译不等于中文分词：实现时需用实际内容验证检索，包括中文品牌、连续中文句子中的业务术语、数字型号、中英文混合词。

默认分词不满足验收时，为本地搜索配置一致的索引及查询分词规则，必要时引入中文分词工具。品牌别名和常见称呼通过正文或术语表补充，不先承诺语义检索或自动同义词理解。

验收用词从实际收录文章中选取，包含标题词、正文词、型号和无结果词，避免用未收录内容验证命中率。

## 7. 更新时间

- 开启 VitePress 的 `lastUpdated` 功能。
- 以每个 Markdown 文件最近一次 Git 提交时间为准，统一按 `Asia/Shanghai` 展示。
- 正式文章必须先提交到 Git；未提交草稿可能没有可展示时间。
- 构建环境需要完整或足够的 Git 历史，避免浅克隆造成所有文章显示同一时间。部署时检查实际历史获取方式，必要时在构建前补取历史。
- 独立图片更新不会天然改变引用文章的 Git 时间；替换图片时同步更新该文章的说明或引用，并提交文档文件。
- 验收需覆盖两篇不同时间提交的文章，以及只改一篇、仅重新部署的情况。

Git 的提交时间代表提交修改的时间，不使用文件系统修改时间，也不以网站构建时间代替文章修改时间。

## 8. 构建与部署配置

在项目根目录设置脚本（实施时写入 `package.json`）：

```json
{
  "scripts": {
    "docs:dev": "vitepress dev docs",
    "docs:build": "vitepress build docs",
    "docs:preview": "vitepress preview docs"
  }
}
```

Cloudflare Pages 拟配置如下，区别于将 VitePress 放在仓库根目录的官方示例：

| 配置 | 值 |
| --- | --- |
| 项目根目录 | 仓库根目录 |
| 生产分支 | `main`，以实际仓库为准 |
| 构建命令 | `npm run docs:build` |
| 输出目录 | `docs/.vitepress/dist` |
| Node.js 版本 | 与本地一致的受支持 LTS 版本，实施时固定 |
| 网站地址 | 初期使用平台分配的 `*.pages.dev` |
| 自定义域名 | 可选，确定域名后绑定 |

首次部署步骤：准备工程与锁文件 → 本地构建检查 → 推送正式内容 → 创建 Pages 项目并连接仓库 → 配置构建与输出 → 验证文章直接访问、搜索与时间 → 用员工手机试用。

日常更新步骤：修改 Markdown 和配图 → 本地预览 → 提交并推送 → 等待部署成功 → 检查正式网址。

发布失败时检查构建日志，不用未经验证的产物替换正式版本。需要恢复内容时可回退对应 Git 修改并重新发布；也可使用平台已有成功部署进行回滚。保留最近成功部署的信息。

## 9. 免费额度与托管选择

截至调研日，Cloudflare Pages 免费套餐包含每月 500 次构建、每站点最多 20,000 个文件；平台分配域名可用于初期试用。具体政策以部署时官方说明为准。自购品牌域名及其续费单独计算，不纳入免费托管承诺。

第一版计划使用静态托管，不引入 Functions、数据库、对象存储或付费搜索。图文、模型及动画规模和更新频率在免费额度内时，预期无需托管月费。代码建模与动画制作仍需开发工作量；免费托管不代表内容与演示无需制作成本。

员工主要使用手机，仍需在实际所在网络验证访问表现。本方案不保证海外托管在中国大陆的连接质量。若实际体验不达标，可将同一套静态产物迁移到其他托管平台或现有服务器，无需重写内容系统。

Vercel 免费 Hobby 套餐限制为个人非商业用途，不作为公司知识库的免费部署方案。

## 10. 验证与交付顺序

1. 先搭建文档站结构：中文主题、通用知识四模块（腕表功能含基本认知与深入理解）、四个品牌及可按需添加系列／型号的导航结构；不等待收齐内容，测试题本阶段暂缓。
2. 配置搜索与更新时间，覆盖真实中文术语和两个不同提交时间。
3. 完成手机目录、文章内目录、图片查看和宽表格适配。
4. 为基础结构章节制作 3D 样例，为腕表功能深入文章制作复杂功能动画样例，验证手机交互、文字对应、加载与失败降级，再按清单扩展。
5. 按需整理通用知识及品牌知识的正式知识文章，检查基础与深入内容的分层、六种基础材质、品牌侧重、指定系列、通用章节、型号与变种归属、品牌材质比较维度、图文及动画覆盖、引用和站内链接。
6. 运行生产构建，预览首页、文章深链接与 404，检查项目文档未进入产物和搜索索引。
7. 配置部署并开展员工手机实际网络试用，记录结果再确定长期域名与托管。

本期不引入复杂测试框架。使用构建校验、必要的链接检查和针对需求文档验收项的人工验证；如增加定制搜索逻辑，再针对检索行为增加有意义的测试。
